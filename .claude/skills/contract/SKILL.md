# Contracts

Generated by `npm run plan -- <TICKET>` from the IR; each file has exactly one owner unit (its header says so).
Do not edit contracts by hand: change the IR and re-plan. A unit that needs a change to someone else's
contract adds an owed.yaml entry (docs/CONVENTIONS.md#owed-yaml).

- `contracts/openapi/<service>.yaml`: OpenAPI 3.1. Path params use `{id}`. Success codes: GET/PUT/PATCH 200,
  POST 201, DELETE 204. Every operation documents 400/401/403 (and 404 with a path param) using the shared
  `Error` schema from docs/CONVENTIONS.md#errors. `x-roles` lists the roles allowed; every other role gets 403.
- `contracts/events/<name>.json`: JSON Schema with `event`, `occurred_at`, `data`.
- `contracts/db/<entity>.json`: table, columns, types, nullability, `pii`, enum `check_values`, `references`.
  Implement migrations that create exactly this (plus indexes you need), with a working `down`.

Both sides test the contract: the provider validates its responses against the schema; the consumer mocks
from the schema, never from the provider's code.
